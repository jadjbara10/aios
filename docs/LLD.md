## Kernel + bootloader (Phase 0-1)

### Purpose

The AIOS Kernel is the immutable cognitive substrate. It owns memory, scheduling, IPC, and capability-based security. Everything generated by AI (drivers, agents, tools) runs above it in sandboxes and CANNOT mutate the kernel security base.

### Module map (Phase 1)

main.rs - _start entry, BootInfo validation, boot orchestration. bootinfo.rs - RDI handoff mirror. serial.rs - COM1 16550 UART, spin::Mutex-guarded. logger.rs - log::Log impl routing to COM1. panic.rs - #[panic_handler], dump + cli/hlt.

### Safety contract

Safe Rust everywhere except: raw I/O port access (serial write/read), CPU halt instructions (hlt), and interrupt disable (cli). Every unsafe block carries a SAFETY comment explaining the invariant. The build sets panic=abort to forbid unwinding across FFI.

### Boot contract (from bootloader)

CPU in 64-bit long mode, paging enabled, interrupts disabled, RDI -> BootInfo pointer. _start is #[no_mangle] extern "C" and diverges. BootInfo.version is validated first; on mismatch we log an error but continue (Phase 1 logging is independent of the handoff). The bootloader (crates/bootloader) is the sole producer of BootInfo.

### Bootloader LLD (new)

crates/bootloader is a uefi-rs PE32+ app. efi_main probes GOP, reads RSDP from config tables, snapshots the memory map, loads the embedded kernel ELF (elf.rs) into LOADER_DATA pages, allocates a 64 KiB kernel stack, calls ExitBootServices, then invokes entry.asm::handoff_to_kernel(entry, &BootInfo, cr3=0, stack_top). entry.asm installs the stack, optionally swaps CR3, sets RDI=&BootInfo, cli, jmp rax. Phase 2 passes page_tables::cr3() to switch to AIOS-owned paging.

### Out of scope (this drop)

GDT/IDT installation, interrupt handling, SMP, heap allocator, scheduling, IPC, full page-table rebuild. All tracked by AIOS-005 and downstream Phase 2 issues.

## Memory Subsystem (Phase 2)

### Purpose

The memory subsystem provides the immutable physical-and-virtual memory substrate that every other AIOS subsystem stands on. After Phase 2 bring-up, the kernel owns its own address space (no UEFI identity map), its own physical frame pool (a bitmap over EfiConventionalMemory), and its own kernel heap (a bump allocator exposed via #[global_allocator]). Every allocation in the kernel is capability-scoped: a Frame handle can only be obtained through the frame allocator, and a heap region can only be obtained through the global allocator. AI-generated agent code running in Phase 3 sandboxes never receives a raw Frame — it goes through the capability broker, which is the mechanism by which the Immutable Core Principle is enforced at the memory layer.

### Frame allocator

BitmapFrameAllocator owns a 2 MiB static bitmap in BSS — one bit per 4 KiB frame — covering the first 64 GiB of physical RAM. init() walks the UEFI memory map delivered via BootInfo.memory_map_ptr / memory_map_len, and for every EfiConventionalMemory descriptor sets the bits for each of its number_of_pages frames. alloc_frame() does a linear scan from frame 0 up to a high-watermark for the first clear bit, clears it, and returns the physical address. free_frame() sets the bit back. The bitmap is intentionally simple; Phase 3 will swap it for a buddy allocator with per-CPU freelists. A high-watermark caps the scan so early-boot allocs stay cheap. Frames above 64 GiB are detected and logged once but not addressable in the Alpha.

### Heap

heap.rs exposes a BumpHeap over a 4 MiB static byte array in BSS with a monotonically-rising cursor. BumpHeap implements alloc::GlobalAlloc — alloc() aligns the cursor up to layout.align(), advances it by layout.size(), and returns the pointer; dealloc() is a no-op that logs a warning at debug level; alloc_zeroed() delegates to alloc() and zero-fills the result. The BumpHeap is wired in as the kernel #[global_allocator] via a single static, and a #[alloc_error_handler] halts on OOM with a serial log entry. This is deliberately primitive — the kernel allocates very little during boot and almost nothing is freed. Phase 3 replaces BumpHeap::alloc/dealloc internals with a buddy + slab backed by the frame allocator; the #[global_allocator] static and every alloc::* call site stays unchanged.

### Paging activation

paging.rs ends the UEFI identity-map era. activate() reads the bootloader-supplied CR3 (the AIOS-owned PML4 built by crates/bootloader/src/page_tables.rs, which identity-maps the first 1 GiB with 2 MiB huge pages and maps the kernel image into the high half) and loads it via the unsafe asm sequence mov cr3, rax (with interrupts held off from the entry.asm handoff). After activation, the kernel owns its address space. map_page(vaddr, paddr, flags) and unmap_page(vaddr) walk PML4 → PDPT → PD → PT manually, allocating missing intermediate tables from the frame allocator on demand. Edits are unsynchronised in Phase 2 (uniprocessor, IF=0); unmap_page invalidates the local TLB entry with invlpg. Phase 4 will add a TLB-shootdown IPI for SMP.

## Interrupt Subsystem (Phase 2)

### GDT & TSS — flat kernel segments + IST for double fault

AIOS Phase 2 brings up a minimal flat kernel-segmentation model on x86-64. The GDT carries five entries: a null descriptor (slot 0), a kernel-code segment with access byte 0x9A (slot 1, selector 0x08), a kernel-data segment with access byte 0x92 (slot 2, selector 0x10), and a 64-bit TSS descriptor spanning slots 3-4 (selector 0x18). Both segments are flat (base=0, limit=0) with the L bit set on the code segment for 64-bit mode.

load_gdt() issues lgdt against a 10-byte pseudo-descriptor, then reloads DS/ES/FS/GS/SS via "mov sreg" and CS via a far return (push cs; lea tmp,[rip+1f]; push tmp; retfq). The 64-bit TSS reserves interrupt_stack_table[0] as the double-fault stack — a 16 KiB static buffer whose top-of-stack address is written to IST[0] before ltr selects the TSS descriptor. This guarantees that a #DF triggered by a kernel stack overflow always lands on a known-good stack rather than the corrupted one.

### IDT — 256-entry table, lidt load

The IDT is a flat array of 256 16-byte interrupt-gate descriptors, 16-byte aligned per the AMD64 spec. Each IdtEntry encodes the handler's RIP (split into low/middle/high 16+16+32 bits), the kernel-code selector 0x08, an IST index (0-7), and a flags byte (gate type + DPL + present).

GateFlags is a bitflags struct exposing INTERRUPT_64 (0x0E), TRAP_64 (0x0F), DPL_3 (0x60), and PRESENT (0x80). Idt::new() zero-initializes the table (every gate is "missing"); set_handler(idx, handler) installs a present ring-0 64-bit interrupt gate at vector idx with IST=0; set_handler_with() adds an explicit IST slot for #DF (IST=1). load() issues lidt against a 10-byte Idtr pseudo-descriptor and is called once on the boot CPU after gdt::load_gdt() + gdt::load_tss(). The IDT static lives for the lifetime of the system.

### Exception handlers — x86-interrupt ABI, register dump, halt

Exception handlers use the nightly extern "x86-interrupt" ABI (gated by #![feature(abi_x86_interrupt)] at the crate root) so the compiler emits the correct prologue/epilogue: caller-saved GPRs are preserved and the epilogue is iretq.

Four handlers are delivered in Phase 2: divide_by_zero (#DE, vector 0, no error code), page_fault (#PF, vector 14, error code + CR2 read via "mov rax, cr2"), double_fault (#DF, vector 8, routed to IST[0] for stack-overflow safety, returns !), and general_protection_fault (#GP, vector 13, error code). Each handler logs the vector, the saved RIP from the ExceptionStackFrame, and (where present) the error code + CR2 via log::error!, then calls halt_forever() which executes "cli; hlt" in a loop. None of the fatal handlers return; Phase 3 will replace #PF with a real page-fault dispatcher once the frame allocator is online.

### PIC — 8259 remap to 0x20/0x28, EOI

The legacy 8259 PIC pair (master at 0x20/0x21, slave at 0xA0/0xA1) is initialized via Pic::remap(0x20, 0x28) which executes the canonical ICW1-ICW4 init sequence: ICW1 starts the init on both PICs, ICW2 sets the vector offset (master 0x20-0x27, slave 0x28-0x2F) so legacy IRQs no longer collide with CPU exceptions (vectors 0-0x1F), ICW3 wires the cascade (master sees slave on IRQ2, slave responds on cascade input 2), and ICW4 selects 8086 mode with auto-EOI off.

Each ICW write is followed by an io_wait() (a byte write to ISA POST port 0x80) to give slow ISA devices time. mask_all() writes 0xFF to both IMRs. end_of_interrupt(irq) issues the OCW2 non-specific EOI (0x20) to the slave first then the master for IRQs >= 8 — the canonical cascade EOI sequence. The local APIC and IO-APIC are deferred to Phase 3 (AIOS-010); the 8259 remains as an early-boot and fallback path.

Files: `crates/kernel/src/interrupts/gdt.rs`, `crates/kernel/src/interrupts/idt.rs`, `crates/kernel/src/interrupts/handlers.rs`, `crates/kernel/src/interrupts/pic.rs`

## Scheduler & IPC (Phase 2)

### Task model

Every AIOS execution context — whether an OS thread or a first-class AI agent — is a Task. A Task owns a 16 KiB private stack (allocated via the kernel heap allocator with a 16-byte aligned top) and a saved CpuContext containing the callee-saved subset of the SysV AMD64 ABI (rbx, rbp, r12, r13, r14, r15) plus rip and rsp. TaskState transitions are Ready → Running → (Ready | Blocked | Terminated); only Ready tasks are eligible for pick_next. The bootstrap kinit task reuses the bootloader stack until the first context switch. New tasks are constructed via Task::new_user, which lays out a return-to-trampoline frame (entry point in ctx.rip, argument slot at the stack top) so the first switch into a fresh task lands in entry(arg) with a clean ABI-conformant stack.

### Scheduling

The scheduler is cooperative + preemptive. Cooperative: a task calls yield_now(), which issues an int 0x80 trap; the trap handler saves the caller CpuContext and calls sched::tick(). Preemptive: the timer IRQ (PIT in early boot, Local APIC in Phase 2 / AIOS-008) drives the same tick() entry point on each quantum. The policy is round-robin with a priority placeholder (AIOS-012): pick_next rotates the ready-queue index, demoting the previously-running task back to Ready and promoting the next one to Running. The global scheduler state lives in a static spin::Mutex<TaskList>; the lock is "lock-free-ready" — every critical section is O(1) so contention is bounded to a few hundred cycles per tick. AIOS-009 tracks the per-CPU CAS run-queue successor for SMP.

### Context switch

context_switch(prev: &mut CpuContext, next: &CpuContext) is an extern "C" Rust wrapper around the __sched_switch global_asm symbol. Splitting the asm out lets the compiler treat context_switch as a regular C-ABI call without modeling callee-saved clobbers across inline asm. The trampoline saves the caller callee-saved regs into prev.ctx at the documented field offsets (OFF_RBX..OFF_R15), saves rsp into prev.ctx.rsp, loads next.ctx.rsp into rsp, restores the next task callee-saved regs from next.ctx, pushes next.ctx.rip, and ret-s into it. The first switch into a freshly-spawned task ret-s into entry(arg) because Task::new_user preloaded ctx.rip and the arg slot. Soundness relies on IRQs being disabled (the call site is the timer IRQ top-half or the syscall trap) and the kernel being uniprocessor in Phase 2.

### IPC

IPC is a bounded MPSC Channel<T>: a ring buffer of Option<T> behind a spin::Mutex, with head/tail/len indices. Sender<T> is Clone (multi-producer); Receiver<T> is single-consumer in Phase 2. Every operation authenticates a ChannelCap bearer token against the channel stored cap, so a task without the capability cannot send or receive even if it obtains a raw pointer. try_send returns Err(val) on full or unauthorized; send loops with yield_now. try_recv returns None on empty or unauthorized; recv records the calling TaskId in blocked_recv and yields, so the scheduler can skip the blocked task until a sender clears the blocker. AIOS-011 tracks the full wake path (state flip back to Ready + ready-queue push) and the multi-receiver generalization for Phase 3.

Files: `crates/kernel/src/sched/mod.rs`, `crates/kernel/src/sched/task.rs`, `crates/kernel/src/sched/round_robin.rs`, `crates/kernel/src/sched/ipc.rs`

## Hardware Abstraction Layer (Phase 2)

### Trait surface

The HAL exposes exactly four uniform traits: BlockDevice (read_block / write_block / block_size), InterruptController (enable / disable / eoi), Timer (now_ns / set_frequency), and SerialConsole (write_bytes). Every AI-generated driver and every handwritten driver implements the same trait set against the same signatures, so the kernel can dispatch through a stable vtable without naming the concrete driver crate. Trait methods are intentionally synchronous and infallible in v0.1 alpha - a failed device op logs and halts rather than returning a Result - because the boot-time device set is small and the failure semantics are simpler than propagating errors through the capability check layer.

### Device tree

DeviceDescriptor { id, kind: DeviceKind, vendor_id, device_id, caps } is the registry row. DeviceKind is the coarse enumeration { Block, Net, Gpu, Input, Serial, Timer } and drives which HAL trait the driver must implement. The HAL does not probe hardware itself; instead the driver-gen detection stage calls DeviceRegistry::register as it brings each device online, appending to a Vec behind a spin::Mutex. The kernel enumerates the registry to build its device table, route IRQs, and seed capability grants. Probe by PciAddr (packed seg:bus:dev:fn) is provided for the PCI bus walk; non-PCI devices use their driver-assigned opaque id.

### Capability bus

Every device access requires a Capability<T> - a typed handle wrapping a CapabilityToken (a Copy u64 nonce whose inner field is private, so forging requires the unsafe CapabilityToken::mint). The kernel is the sole entity permitted to mint, grant, and revoke tokens; agent code receives capabilities via IPC and can never construct one in safe code. CapabilityBus is a per-task BTreeMap<TaskId, Vec<(CapabilityToken, target)>> with grant / revoke / revoke_all / check / count operations, all serialized by a single spin lock on the global CAPABILITY_BUS static. Revocation is immediate and unconditional - there is no capability caching layer in v0.1 alpha, so a revoked token fails the very next CapabilityBus::check.

### Integration

The HAL crate (crates/hal/, no_std, deps: spin + log + bitflags) sits above the immutable kernel core and below the driver crates. Generated drivers implement HAL traits and register DeviceDescriptors into the global DEVICES registry during init; the kernel then grants Capability<T> handles from the global CAPABILITY_BUS to tasks (agents) that need device access. Every device syscall first calls CapabilityBus::check(task, token, target); only on success does it downcast to the trait object and invoke the method. This keeps the AI-generated driver layer behind a hard capability boundary - a misbehaving agent literally cannot touch a device it was not granted a capability for.

Files: `crates/hal/Cargo.toml`, `crates/hal/src/lib.rs`, `crates/hal/src/device_tree.rs`, `crates/hal/src/capability.rs`

## AI Engine (Phase 3)

### Engine - local-only inference orchestrator

AIEngine is the top-level handle for on-device LLM execution. It owns a parsed GgufModel, a BPE Tokenizer, and a fixed-window ContextManager. load_model(bytes) maps a GGUF blob read-only from the immutable core FS, validates the header, and constructs a stub tokenizer sized by tensor_count. infer(&mut self, prompt) is the single entry point: it encodes the prompt to token ids, appends them to the context window (evicting oldest slots on overflow), runs a deterministic forward-pass stub, and returns the detokenized echo. Real Q8_0/Q4_K matmul plus fused attention lands in Phase 3.1 (AIOS-014). The engine never issues a network call - all inference is local, satisfying the no-cloud Immutable Core Principle.

### GGUF - llama.cpp container parser

GgufParser::parse walks the GGUF v3 header: 4-byte magic (0x46554747, the four bytes 'G','G','U','F' little-endian), 4-byte version (must be 3), 8-byte tensor_count, 8-byte metadata_kv_count. Byte reads go through read_u32_le / read_u64_le helpers that bounds-check then perform unaligned u8 pointer loads inside an unsafe block annotated with a // SAFETY: justification. GgufDType::{Q4_K, Q8_0, F32} is the supported dtype subset; from_u32 maps the raw id and surfaces AiError::UnknownDtype on miss. The tensor metadata table (name + dims + dtype + offset) is parsed in Phase 3.1 - Phase 3.0 returns an empty tensor table after header validation so the engine contract is testable without a real weights blob. dequantize_q8_0 is a stub that returns the f16 block scale cast to f32; the real scale * q reconstruction with SIMD cvtph2ps lands in AIOS-014.

### Tokenizer - BPE encode/decode

Tokenizer owns a Vec<String> vocab indexed by token id and a Vec<BpeMerge> of (left, right, merged, rank) rules. encode(&self, text) walks the input bytes and maps each to a token id modulo vocab size - a placeholder path that lets the engine round-trip without a trained merges table. decode(&self, ids) walks the id slice and concatenates vocab strings, mapping out-of-range ids to "<unk>" so the decoder never panics. validate(&self, ids) returns AiError::TokenOutOfRange on the first offending id for callers that want strict semantics. The tiny hardcoded vocab example (0="<unk>", 1="<s>", 2="</s>", 3="hello", 4=" world", 5="aios") lives in a module-level comment - the production vocab + merges are loaded from the GGUF metadata KV in Phase 3.1 (AIOS-015). apply_merge_pass is the merge-loop stub that Phase 3.1 replaces with the real greedy lowest-rank BPE merge.

### Context - fixed n_ctx sliding window + KV ring

ContextManager owns n_ctx (the live token budget, default 2048), a Vec<u32> token sequence, and a Vec<KvEntry> KV cache ring sized one slot per live token. append_token pushes a new id; when the window is full the oldest token and its KV slot are evicted via Vec::remove(0) - Phase 3.1 swaps this for a constant-time ring-buffer index. truncate(len) keeps the most-recent len ids using an in-place ptr::copy shift inside an unsafe block annotated with a // SAFETY: justification (drop is bounded by tokens.len(), ptr::copy is memmove-equivalent for overlaps, u32 is Copy so set_len does not leak). reserve(additional) calls try_reserve on both vecs and surfaces AiError::ContextExhausted on alloc failure. clear resets both buffers while keeping capacity. Phase 3.1 (AIOS-015) wires the KvEntry ring into the real per-layer attention kernel.

Files: `crates/ai-core/src/lib.rs`, `crates/ai-core/src/gguf.rs`, `crates/ai-core/src/tokenizer.rs`, `crates/ai-core/src/context.rs`

## Cognitive Runtime (Phase 3)

### Runtime — the think-loop

The CognitiveRuntime is the steady loop that drives the Agent Federation. For every goal it runs plan -> reason -> decide: the Planner turns the goal into a task DAG (delegating the actual decomposition to the AI Engine), the Reasoner weighs evidence into per-task Beliefs, and the Decision Engine selects one concrete Action under a Policy. The runtime owns the AIEngine handle, the Planner, the Reasoner, and the DecisionEngine as plain fields, and run_goal(&mut self, goal: &str) -> Action is the single entry point the Federation calls. Nothing in the runtime mutates kernel state directly — that is forbidden by the gate inside the Decision Engine, so the runtime is a pure producer of proposed actions.

### Planner — goal to task DAG

The Planner takes a natural-language Goal and returns a TaskGraph. Each Task carries an id, a description, a capability tag, and a list of dep TaskIds — together the deps form a directed acyclic graph. The actual goal -> sub-task decomposition is the AI Engine's job (the planner calls engine.decompose(goal)); the planner's responsibility is to wrap that output in a TaskGraph, compute the roots (tasks with no deps), and validate acyclicity with Kahn's algorithm. A cyclic plan is flagged acyclic=false and the Federation layer can refuse to execute it. The topological order is what the Federation walks to dispatch tasks to agents.

### Reasoner — evidence + belief

The Reasoner turns a Task plus a Context of Evidence into a Belief. Each Evidence has a source, a weight (0..=100), and a supports flag. The Reasoner sums supporting and opposing weights additively with saturating arithmetic, then normalizes to a confidence in -100..=100 (negative means "do not execute this task"). It then asks the local LLM, through the AIEngine.chain_of_thought stub, for a rationale string attached to the Belief. The capability is mirrored from the task onto the belief so the Decision Engine can gate on it without re-touching the graph. The Reasoner never picks an action — it only judges confidence.

### Decision Engine — policy + Immutable Core gate

The Decision Engine selects one Action from a slice of Beliefs under a Policy. Action is an enum: Run (execute locally), Delegate (hand to a federated AgentId), Ask (clarify with the principal), or Halt (stop). The Policy exposes min_confidence and allow_delegation thresholds, but it deliberately has no field that can weaken the Immutable Core. The SafetyGate is a hard-coded structural check: any proposed Run or Delegate whose capability is KernelMutation is converted to Halt with reason "Immutable Core: kernel mutation forbidden" before it leaves the module. The gate is the load-bearing safety property of the whole runtime — no kernel-mutating action can ever reach the Federation, regardless of confidence or policy.

Files: `crates/cognitive-runtime/src/lib.rs`, `crates/cognitive-runtime/src/planner.rs`, `crates/cognitive-runtime/src/reasoner.rs`, `crates/cognitive-runtime/src/decision.rs`

## Multi-Agent Federation (Phase 4)

### Federation

Every AIOS application is an Agent identified by a stable 64-bit AgentId (0 reserved for Root). The Federation registry owns the live Agent set and is the single source of truth for capability-gated dispatch — the kernel refuses to deliver Effects whose issuer does not hold the named capability. Agents are deterministic, side-effect free apart from the Effect they return, and run single-threaded per CPU. Federation::dispatch routes by AgentId and reaps unknown recipients with Effect::Halt.

### Message bus

The AgentMessageBus is a pub/sub layer atop the kernel IPC channels (sched::ipc). Each agent owns a bounded MPSC mailbox (MAILBOX_DEPTH = 32) implemented as a ring of Option<MailboxEntry>; backpressure returns false from publish so the caller can apply drop-oldest or block. Direct delivery routes by AgentId; broadcast fans out to all Topic subscribers. CapRequest payloads are dropped at the bus when the recipient lacks the named capability — subscribers never see forbidden caps.

### Root agent

Exactly one RootAgent lives in the Federation, always at AgentId::ROOT. It owns an opaque CognitiveRuntimeHandle (the kernel resolves it to a runtime control-block address; crt_status reads the status byte via read_volatile under a documented SAFETY block). Root is the only agent that declares Capability::Spawn, so it is the only agent whose Effect::Spawn the kernel will honor. It routes incoming goals to specialists by prefix (net:/hw:/code:) and aggregates their Partial/Final replies.

### Specialists

Three built-in specialists map 1:1 to subsystems: NetworkAgent (wraps netstack, holds only Capability::Net), HardwareAgent (wraps HAL + driver-gen, holds only Capability::Hardware), CodingAgent (generates Rust source and submits to the sandbox, holds only Capability::Code). Each implements Agent, translates a prefixed Goal into the appropriate unsafe extern "C" ABI call (netstack_send / hal_read32 / sandbox_submit), and replies to Root with a Final payload — never holding more capability than the task requires.

Files: `crates/agents/src/lib.rs`, `crates/agents/src/bus.rs`, `crates/agents/src/root.rs`, `crates/agents/src/specialists.rs`

## Knowledge System (Phase 4)

### Knowledge Objects

Every File, Note, Memory, and Tool in AIOS is a Knowledge Object (KO): a content-addressed blob with a stable 128-bit KoId derived from a 256-bit content hash. A KO carries a unit-norm f32 embedding (produced by the canonical Embedder) and a set of capability tags that travel with the object, so policy enforcement is local to the KO rather than the caller. KoKind discriminates the four kinds; KnowledgeStore provides put/get/query and is the single mutation boundary. Phase 4.1 will swap the in-memory Vec for a persistent object log on the immutable core without changing the store trait surface.

### Vector index

The VectorIndex is a flat slab of (KoId, embedding) pairs backing all semantic recall. Because embeddings are unit-norm, cosine similarity reduces to a dot product; search() does an O(N*D) brute-force scan plus a partial sort to return top-k (KoId, score) pairs in descending order. insert() replaces by KoId and rejects dimension mismatches; remove() uses swap_remove for O(1) deletion. HNSW (hierarchical navigable small-world graphs) replaces the brute-force scan in Phase 4.1 once the heap allocator and object log are stable; the search() signature will not change, so callers are forward-compatible.

### Memory tiers

Memory is staged into two tiers. ShortTermMemory (STM) is a fixed-capacity ring (default 32 slots) of recent KoIds with per-slot hit counters; push() is O(1) and lossy (oldest slot overwritten when full), and bump() increments the hit counter of a resident KoId on each probe. LongTermMemory (LTM) is a VectorIndex-backed store: remember() normalizes a KO embedding and inserts it; recall() returns top-k by cosine. STM is fast and bounded; LTM is slower to write but enables semantic search. The two tiers compose so the working set lives in STM and the durable, searchable set lives in LTM.

### Embeddings

The Embedder trait is the single text-to-vector abstraction: embed(&str) -> Vec<f32> with a fixed dim(). The canonical implementor is the AI Engine (crates/ai-core), which owns the model and tokenizer. A deterministic LocalEmbedder stub (FNV-1a hash spread across dimensions, then L2-normalized) exists for host tests and early boot before the AI Engine is online; it is explicitly non-semantic and is swapped at the dependency-injection boundary with no caller changes. normalize() is the shared L2 path used by both the stub and the store before insertion into a VectorIndex.

Files: `crates/knowledge/src/lib.rs`, `crates/knowledge/src/vector.rs`, `crates/knowledge/src/memory.rs`, `crates/knowledge/src/embedding.rs`

## Network Stack (Phase 5)

### Stack — native ETH/IP/ARP over a HAL device

The netstack crate owns a Box<dyn HalDevice> (the NIC driver, e.g. crates/drivers/e1000) and exposes a single poll-driven entry point NetStack::poll(). Each poll drains the NIC RX ring one frame at a time into a 1536-byte scratch buffer and dispatches by EtherType: ETH_TYPE_ARP (0x0806) into the ARP responder, ETH_TYPE_IPV4 (0x0800) into the IP demuxer. There is no async runtime and no third-party smoltcp-style dependency — every frame is built and parsed in-crate. MacAddr and Ipv4Addr are primitive newtypes with const constructors so the bootloader can stamp the link-layer addresses before the heap is online. The neighbour cache and ARP reply path are stubbed to Phase 5.1 (AIOS-022).

### TCP — RFC 793 state machine, sockets, seq/ack

tcp.rs implements a subset of the RFC 793 figure-6 state machine: Closed, SynSent, SynReceived, Established, CloseWait, FinWait1, FinWait2, LastAck. TcpSocket owns the local/remote 4-tuple, snd_nxt/rcv_nxt sequence numbers, and a Vec<u8> receive buffer. on_segment drives the transitions: a SYN|ACK in SynSent advances rcv_nxt and enters Established; payload in Established extends the rx buffer and bumps rcv_nxt by the payload length; FIN bumps rcv_nxt by one and enters CloseWait; RST tears down to Closed. The ISN is currently a monotonic rdtsc seed; real RFC 6528 ISN, the retransmit queue, congestion control (cwnd/ssthresh), and the TIME-WAIT 2MSL timer are explicitly deferred to Phase 5.1.

### DNS — query build + A-record parse + cache

DnsResolver holds a Vec<(String, Ipv4Addr, u32)> cache and a monotonic 16-bit query id. resolve(name) returns a cached A-record if present and TTL > 0 (decrementing the TTL on each lookup), else None. build_query(name) emits a minimal DNS message: 12-byte header (RD=1, QDCOUNT=1) followed by length-prefixed labels, a root terminator, and QTYPE=1/QCLASS=1. ingest(name, resp) parses the response — skipping the question section with a compression-pointer-aware skip_name helper — walks the answer RRs, and seeds the cache with the first A-record (rtype=1, rdlen=4) at a 300-second TTL. No DNSSEC, no TCP fallback, no EDNS(0) — all Phase 5.2.

### HTTP/TLS — HTTP/1.1 client; TLS handshaker stub

HttpClient::get(url, server_ip, sock) parses a scheme://host[:port]/path URL (defaulting to 80/443 by scheme), drives TcpSocket::connect, stages a minimal HTTP/1.1 GET (Host, Connection: close, User-Agent: AIOS/0.1) through sock.send, then drains sock.recv into a buffer and parses the response: status line (code parse), header block split on CRLF with lowercased keys, and body after the blank-line separator. TlsHandshaker is a deliberately inert stub — established is always false and step() always returns false — because a real rustls-like ClientHello→ServerHello→Certificate→KeyExchange→ChangeCipherSpec state machine is Phase 5.2 work tracked under AIOS-023. The stub exists now so the HTTP client surface compiles against https:// URLs without lying about crypto readiness.

## Driver Generation System (Phase 6)

### Pipeline

The driver-gen subsystem runs a four-stage pipeline per boot: detect -> generate -> sandbox -> install. The HAL bootstrap invokes run() once the Immutable Core is sealed and the capability table is online. Detection failures, generation failures, and sandbox load failures are all quarantined per-device; no single device can panic the kernel. The whole flow is fully AI-driven with no human in the loop — a device appears, the AI authors a Rust no_std driver for it, the sandbox compiles and seals it, and the HAL DeviceRegistry publishes it.

### Detection

Enumeration walks the PCI tree (bus 0..255, dev 0..31, func 0..7) by issuing legacy config-space I/O through ports 0xCF8 (CONFIG_ADDRESS) and 0xCFC (CONFIG_DATA). The address dword is encoded per PCI Local Spec r3.0 sec 2.2.2.2 (enable bit + bus/dev/func/dword-offset). Each function is decoded into a PciDevice carrying vendor, device_id, full 24-bit class code, and all six BARs. A known-ID table short-circuits AI generation for hand-verified devices (e1000, VirtIO net/blk, QEMU framebuffer, etc.). Every outl/inl block carries a SAFETY comment.

### Generation

For each surviving device, generate_driver(dev) maps the PCI base-class byte to a HAL trait (BlockDevice for 0x01, NetDevice for 0x02, Framebuffer for 0x03, MediaDevice for 0x04, BusController for 0x0C, else GenericDevice) and builds a natural-language prompt. The prompt carries exactly three things: the PCI class code, all six decoded BAR values, and the vendor/device id. It deliberately carries NO kernel address, capability token, or pointer — the model literally cannot touch the Immutable Core from the prompt alone. The AI Engine returns Rust no_std source text that is never linked or executed directly.

### Sandbox

Sandbox::compile_and_load is the trust boundary. It compiles the generated source in an isolated toolchain (crates/compiler-host), mints capabilities ONLY for the BARs the device declared (zero-valued BARs are skipped), loads the blob + caps into an isolated address space, and registers the result in the HAL DeviceRegistry. The kernel capability table (crates/hal::caps) rejects any out-of-scope capability request, so a generated driver cannot reach the kernel security base even if the AI output is adversarial. The Immutable Core Principle is enforced structurally, not by trusting the model.

Files: `crates/drivers/src/lib.rs`, `crates/drivers/src/detect.rs`, `crates/drivers/src/generate.rs`, `crates/drivers/src/sandbox.rs`

## AI GUI (Phase 7)

### Desktop

The desktop owns the UEFI GOP framebuffer the bootloader left behind and runs a single compositor loop: poll input -> route to the focused agent -> composite back-to-front -> flip. The loop is driven by run(), called from the kernel main thread once the framebuffer BootInfo field is non-null; it never returns. Each iteration of tick() is one frame. There is no scheduler preemption yet — the loop bounds on the input queue going idle and yields with core::hint::spin_loop. The compositor walks WindowManager::iter_z_back_to_front and blits every agent surface, then draws a 1px violet border and the window title via draw_text. No unsafe lives in the desktop module itself; every volatile store is delegated to Framebuffer::put_pixel, which carries the single SAFETY comment for the whole crate.

### Framebuffer

Direct linear framebuffer ops on the UEFI GOP mode handed off in BootInfo.framebuffer. We assert 32 bpp xrgb8888 — any other mode panics at boot (the bootloader already selects the preferred 32-bpp mode). put_pixel bounds-checks (x, y) against width/height and then writes through core::ptr::write_volatile so the scan-out reads fresh pixels — this is the only unsafe block in the crate. fill_rect / draw_rect tile put_pixel; blit copies an agent surface row-major with per-pixel clipping (transparency lands with AIOS-026). A hand-crafted 8x16 bitmap font (FONT table) covers space, basic punctuation, digits 0-9, and uppercase A-Z; unknown characters fall back to a blank cell via font_lookup. draw_text advances 8 px per glyph, 16 px per line. No GPU yet — Phase 8 will introduce a 2D accelerator behind the same Framebuffer API.

### Windows

Z-ordered WindowManager holds every agent window in a Vec<Window> and tracks the focused window id. spawn lands a new window on top (highest z) and steals focus; close removes a window and refocuses to the next-highest z; focus raises a window to the top of the z-stack; move_window updates its origin (advisory — the compositor clips on draw). Each Window carries the AgentId that owns it, plus a Vec<u32> xrgb8888 surface the agent paints via Window::put. click_focus hit-tests a mouse press top-first (Reverse(z) sort) so a click lands on the visually topmost surface and then re-raises it. focused_agent returns the route target for keyboard events. iter_z_back_to_front yields a back-to-front iterator for the compositor. There is no overlap negotiation — agents own their geometry; the compositor paints whatever they ask.

### Input

The kernel IRQ layer pushes raw PS/2 set-2 scancodes and absolute mouse positions into an InputQueue — a spin::Mutex<Vec<InputEvent>> ring with capacity 256. The desktop drains it once per frame via poll() until empty. InputEvent is a Copy enum: KeyDown(u8) / KeyUp(u8) / MouseMove(i32,i32) / MouseDown(i32,i32) / MouseUp(i32,i32). Mouse coordinates are absolute (framebuffer-space) so the GUI can hit-test directly without maintaining a cursor accumulator. Keyboard events route to the agent owning the focused window (WindowManager::focused_agent -> window::dispatch_key, which bridges into crates/agents once AIOS-014 lands). Mouse-move updates the WindowManager hover slot; mouse-down hit-tests top-first and refocuses the clicked window. Input is lossy under flood — the IRQ handler drops the oldest event rather than blocking. USB HID lands in AIOS-019.

Files: `crates/gui/src/lib.rs`, `crates/gui/src/framebuffer.rs`, `crates/gui/src/window.rs`, `crates/gui/src/input.rs`
